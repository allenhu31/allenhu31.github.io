Network Incident Case

MAC Flapping and HSRP Instability on Core Switches

A production troubleshooting case from the 2009-2011 IDC operations period, involving MAC address flapping, frequent HSRP state changes, 99% CPU utilization, and Layer 2 loop isolation.

Incident Description

At 15:50 on June 23, the South China and North China monitoring systems reported dynamic service access issues in the South China region. After logging in to the 4506C and 4506D switches, I found a large number of MAC address flapping logs, frequent HSRP state transitions, and CPU utilization reaching 99% on both core switches.

Multiple departments reported that affected service IP addresses became slow to access or completely unreachable.

Actions Taken

  • Confirmed monitoring alarms and logged in to both 4506C and 4506D switches despite slow management access.
  • Identified MAC flapping logs, HSRP state transitions, and 99% CPU utilization.
  • Reported the planned troubleshooting steps according to the incident handling process.
  • Determined that the symptoms were likely caused by a Layer 2 loop.
  • Shut down port G2/6 on switch 4506D at 15:57 to isolate the suspected link.
  • Observed CPU utilization return to normal and MAC flapping disappear.
  • Re-enabled port G2/6 at 16:04 and confirmed all affected services recovered at 16:05.
  • Continued monitoring until 18:00 with no further abnormal events.

Root Cause Analysis

The symptoms indicated an STP failure that caused a Layer 2 loop between 4506C, 4506D, and access-layer switches. Broadcast packets circulated repeatedly, consuming CPU and bandwidth resources on the core switches. No clear abnormal log was found before the first MAC flapping event, so the preliminary conclusion was a possible STP software failure.

Follow-up Optimization

I recommended enabling UDLD and STP loop protection mechanisms on all Layer 2 links in the South China IDC, and drafted an implementation plan named Solution for Preventing Layer 2 Loop Incidents.
