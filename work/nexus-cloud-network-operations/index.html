Operating and Troubleshooting a Large-Scale Cisco Nexus-Based Cloud Network

During the China Mobile Cloud Southern Base project, I operated a large-scale cloud network based on Cisco Nexus N7018, Nexus 5545, Nexus 2048, vPC, FEX, and VRF.

Architecture Context

The network used vPC, FEX, and VRF extensively. At the time I left the project, the VRF count had reached the platform limit of 4,096. The architecture did not use VDC, which increased the importance of careful change control and fault-domain design.

Production Incidents

  • In July 2014, an ACL configuration change on Nexus N7018 triggered a software bug and caused a full network outage.
  • In November 2014, a syslog configuration change on Nexus 5545 triggered another software bug and affected roughly half of the cloud services.
  • During a Nexus 5545 system upgrade, a full outage occurred while upgrading the second device, and Cisco recommended suspending the upgrade process.

Technical Analysis

The main architectural risks were related to vPC peer-link behavior, STP interaction, and the broader Layer 2 design. Even routine changes required careful assessment because configuration changes, software defects, and device reloads could create broad service impact.

Key Takeaways

This experience strengthened my understanding that large-scale data center stability depends not only on advanced technologies, but also on architecture simplicity, clear failure domains, software maturity, and strict change management.
